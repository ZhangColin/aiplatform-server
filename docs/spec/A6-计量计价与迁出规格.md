## 0. 总则

- **计价与计量同址**：费用换算 + 单价表全部落 **base.metering**（A1 只定「存储只记 token」，本票定换算归属）——迁出独立服务时再看拆成一个还是多个服务（§5）。
- **零商业概念（CONTEXT 语义改写，原「零钱概念」）**：存储只记 token；换算只出**平台成本**（机械乘法）；无加价 / 售价 / 账单 / 发票。加价是商业策略，归业务层计费（07 票出局项重启时的事），计量止步于平台成本。
- **少配置、多落库**：单价表落库不落配置文件——迁出时数据随库走，配置会留在应用侧。
- 依赖方向不变：业务 → 计量 → 埋点；单价表不是业务层下发（研究稿 F4.3 原案），**表就在计量上下文内**，业务层零感知。

## 1. 单价表 `met_price_entries`

```sql
-- provider × model × token 档位 × 币种，带生效区间（研究稿 F4.3 草案落位）
id PK
provider        -- 'deepseek' / 'anthropic' / ...（与 UsageEvent.provider 同键）
model           -- 与 UsageEvent.model 同键（单价表匹配键）
token_kind      -- 五档枚举：input / output / cache_read / cache_write / reasoning
unit_price      -- numeric(12,8)，每 token 单价（如 $1.5/M = 0.0000015）
currency        -- 'USD' / 'CNY'（按 provider 官方计价币种）
effective_from  -- timestamptz
effective_to    -- timestamptz 可空（空 = 当前行）
created_at
-- 唯一约束 (provider, model, token_kind, effective_from)
```

- **改价 = 关旧行（`effective_to` = now）+ 开新行**——append 式，不 UPDATE 单价；事件按 `ts` 落入生效区间匹配单价，**历史成本不漂移**。
- **单价数值以各官方定价页实时值为准**（研究稿 F1 纪律：不摘抄易过期数字），种子数据在实现票维护。
- **维护入口**：v1 手工 SQL + 启动种子（现役模型：demo `Role.java` 档位 deepseek-v4-pro / deepseek-v4-flash）；维护 API 不建——挂 fog「管理后台」生长点（届时 API 随 UI 一起长）。
- **缺价语义**：某 `(provider, model, token_kind)` 无生效行 → cost 对应分量出 **null（未配价）**，token 照记照聚合，查询不阻断、不伪装成 0。

## 2. 费用换算（查询侧，平台成本口径）

- **换算位置**：base.metering **查询侧现算**，不物化 cost 列（量级是迁出后的问题，Phase A 单机无压力）；事件存储维持零钱。
- **公式**：`平台成本 = Σ (token_kind 用量 × 事件 ts 时点生效单价)`，**按币种分桶**输出（如 `{USD: 1.23, CNY: 4.56}`），**不折算**单一本位币（引入汇率 = 过度设计）。
- **端口扩展**（A1 §2.1 签名微扩，实现片可再调）：

```java
public interface UsageQueryPort {
    UsageSummary bySubject(String subject, Instant from, Instant to);      // A1 既有
    // UsageSummary 扩展：cost = Map<Currency, BigDecimal>（币种分桶）
    //                    + unpriced 标记（有 token 无单价的档位集合，前端示「未配价」）
}
```

- 单价表对内（base.metering 私有表），不经端口暴露——换算是计量上下文的内部能力，对外只出结果。

## 3. 查询面扩展（`GET /api/projects/{id}/usage`）

A1 §2.5 既定：总量 + 分模型 / 分角色聚合。本票增量：

| 增量 | 说明 |
|---|---|
| **cost 字段** | 平台成本，币种分桶 + 未配价标注（§2） |
| **按期聚合** | 按 `iterationId` groupBy；数据来源 = `UsageContext.dims` 新增 **`iterationId`**（business.project 编排 runTask 组装时带上，A1 dims 透传缝现成，底座不解释） |

- **期归属边界**：
  - `iterationId` 取 **run 发起时快照**——run 中途过门不追改；
  - **期后修复 run 归项目不归期**（A3 §7 期后修复不锁工具）：期已收口后发起的修复链 run 不带 `iterationId`，按期聚合不含它、项目总量含它——**收口期成本定格**，与确认留痕 append-only 封存语义一致。
- **趋势（day 桶）不做**：总量 + 分模型 + 按期已满足「token 用量可见」终点；将来前端要趋势图 = 查询端口加一个时序聚合端点的演化，不锁结构。

## 4. 配额留缝（不实现）

- 参考 Code-Canvas §7.3：项目级 token 配额（0 = 封停、run 起跑前拦截、硬限不中断进行中 run）。
- **缝**：拦截点在 **business.project 编排 runTask 之前**（查累计用量 vs 配额，拦截动作是业务决策）；计量侧零新增能力（累计可查即支撑）。配额数值与展示挂 fog。

## 5. 迁出独立服务

- **触发条件（任一即迁）**：
  1. **billing / 收款启动**——对账要独立性（07 票出局项重启之时）；
  2. **出现第二个服务消费方**要接计量；
  3. **Phase B 上云多实例部署**。
- **形态：四段整体迁**（存储 + 聚合 + 换算 + 查询 REST 化）——A1 既定缝落地：sink / query 适配器换 REST，业务域与 agentengine 不动；**单价表随库走**（落库决策的下半句）。
- **拆分形态迁出时再定**（fog）：单服务 vs 计量 / 计价分离——触发时的真实需求决定，现在不预设。

## 6. AI router 解耦（fog 逼近）

- **计量 ≠ 路由，解耦**。模型选择 / 档位路由属 **base.agentengine**（`AgentModelConfig` 直配起步）及其演化（B0 §3：角色卡存档位、`llm_providers.model_tiers` 映射 / 未来 LLM 网关）——路由职责**永不进计量**。
- 计量是**被动观察者**：adapter 读 usage 上报。若未来 LLM 网关（档位路由 + 统一出海）成形，它是更自然的采集点——埋点从 adapter 挪到网关，**UsageEventSink 协议不变**。
- 地图 fog 改写：「LLM 网关（档位路由 + 统一出海）引入时点与形态——B0 §3 升级路径，与计量迁出解耦」。

## 7. 前端契约预告

- **位置**：项目详情页**用量卡**——总量 / 分模型 / 分角色 / 按期 + 平台成本（币种分桶、「未配价」标注、明确「平台成本口径」字样，不出现「价格 / 费用」暗示售价）。
- **发 issue 时机**：后端实现完、swagger 可验证时（协作约定：完成一块 → 发一个；与 A2–A5 同节奏）。
- 契约细节以 swagger 为唯一正本（ADR-0001），本规格只定要素。

## 8. 验收口径

- **换算正确性**（单测）：五档 × 区间匹配——跨改价边界的两事件各按各时点单价；缺价分量 null 不伪装 0；币种分桶不相加。
- **按期聚合**：`iterationId` 快照语义；期后修复 run 不入任何期、入项目总量。
- **埋点扩展**：run 级 UsageEvent 带 `dims.iterationId`（business 编排组装，片 2 埋点缝扩展）。
- 种子单价与官方定价页核对（实现票维护，数值不进本 spec）。
