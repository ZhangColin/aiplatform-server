## 0. 总则（本票世界观）

- **主链 = 平台自己的业务过程，不是模板**。需求梳理→Demo→开发→测试→验收→收口，就这一条；不按项目类型选择过程、不存在模板管理与配置概念。过程要变 = 业务代码正常演化（demo/CC 把阶段写死 enum 的做法没被推翻，被推翻的只是「模板」这个产品概念）。
- **三层支持模型**（现实项目过程的映射，§1）：开发工具挂**项目**常开；过程状态机挂**期**；「项目状态」是**派生投影**。用户视角没有期——只有提需求/提 bug 与确认。
- **验收锚点 = 技术脊柱**：从需求对话到隔离环境运行（预览）本机全通；不以阶段数、不以过程严谨性为验收。
- 状态与确认**针对于期**；生产部署/运维是平台**基于项目的服务**（Environment kind=prod，Phase B+，见 §7）。

## 1. 三层支持模型

| 层 | 挂什么 | 边界含义 |
|---|---|---|
| **项目级（常开，不锁期）** | dev 工作区与智能体任务（Replit 式工具随用）、任务/bug 系统（A4）、知识资产、需求池、用户对话与反馈、（将来）生产环境服务 | **工具不看期**：期关了，开发平台照样能在工作区下任务修 bug |
| **期级（过程覆盖层）** | 阶段状态机（`prj_iterations`）、四确认（`prj_confirmations`）、阶段计数 | 开发团队的过程组织；v1 每项目 1 期、≥2 期才在 UI 显示 |
| **派生（不落库）** | 项目「开发中/已交付」= 有无 OPEN 期投影；「待确认」= 条件推导 | 单期时投影恰好像项目状态——表象即机制 |

词汇表既定的「任务与项目过程正交」「Bug 项目级记录」即本模型的先声；本票把边界说全（CONTEXT 关键边界新增一行）。

## 2. 期与主链状态机

### 2.1 期实体

- 表 **`prj_iterations`**：`id` PK · `project_id` · `seq` · `stage` · `stage_task_count` · `status(OPEN|CLOSED)` · `closed_at` · 审计字段。**状态机主体是期**（B0 片 5 的 Project.stage/stageTaskCount 随此迁出）。
- 建项目 = 一事务建 Project + 第 1 期（seq=1）；v1 寻址 = 项目的 OPEN 期（每项目至多一个 OPEN）。「开二期」动作 v1 不建（§7）。

### 2.2 主链定义（一条，业务侧代码定义传入 base.process）

```
需求梳理(BA, PRD.md) →〔需求确认·用户〕→ Demo(DEMO) →〔Demo 确认·用户〕
→ 开发(DEV) → 测试(无默认角色, OPC 外包) →〔开发完成确认·开发平台〕
→ 验收(无默认角色, 用户) →〔验收·用户〕→ 关闭(终态)
```

- 阶段条目 = `{名/标签, 默认角色?, 产物清单?}` + 出口门 `{actor, minTasks}`；**角色可空**（测试/验收无默认角色；ARCH preset 保留但**不设段**——开发平台开发期间可手动下 ARCH 角色任务）。
- **收口无「交付」段**：验收门通过 = 期 CLOSED + 项目已交付（一个联动动作）。交付物 = 源码包下载端点常开（一直可用）+ 仓内文档；DELIVERY 角色 preset 保留给想用的人（手动下任务），**G4 不设产物门禁**（简单项目「能跑效果对就行」）。
- 引擎照 B0 片 4：无表、不知业务、不知触发，只管推进/驳回停留/计数。**「模板」一词全仓退役**，引擎入参叫主链定义。

### 2.3 推进触发（编排约定，非引擎语义）

| 出口 | 触发 |
|---|---|
| 门出口（四扇） | 人拍板：approve 推进 / 驳回停留（§3） |
| 开发→测试 | **创建首个测试任务时** advance（发任务即人的显式动作，A4 端点处编排） |
| 验收→关闭 | G4 approve 收口联动（§2.2） |
| 前缀段自动 | 建项目即自动跑 BA（对话展开）；G1 通过自动跑 Demo（完事 preview-ready）。**开发起全手动**（Replit 式工作台）。这是编排对主链前缀的固定行为，不构成配置概念 |

### 2.4 门禁分层

- **引擎管计数**：`minTasks` 按阶段定（需求梳理/Demo/开发/测试 = 1，**验收 = 0**——验收段无 agent 任务）；不满足 409 `PRJ_`。
- **编排管业务谓词**：**需求确认（G1）= PRD 已产出**（#49——BA 判定明确经 `savePrd` 工具写 `docs/PRD.md` 到项目工作区并置项目级 `prd_produced_at` 状态位；查状态位不查文件系统，PRD 产出前门不 ready，计数门禁并行保留）；开发完成确认（G3）= 无未关闭 Bug——approve 前经 task BC 查询端口校验（A4 提供 `hasOpenBugs(projectId)` 类谓词），不满足 409。
- **产物清单只作沉淀入库范围**（approve 时入库，挂 A5），**不作门禁**——宽松/严格是将来业务演化（§7）。**v1 清单仅需求梳理段 PRD.md**：Demo 段留空（index.html 是项目产物、走预览/源码包参考，不入向量库，是否沉淀业务后定——A5 §7）；测试段留空（测试报告走 A4 任务确认挂钩，不落工作区文件）。

## 3. 确认记录

- 表 **`prj_confirmations`**（append-only，只增不改）：`iteration_id` · `kind(需求确认|Demo确认|开发完成确认|验收)` · `decision(通过|驳回)` · `reason` · `account_id` · `decided_at`。
- 驳回 **reason 必填**；驳回一律**停留当前阶段**（验收驳回停留验收段，开发平台照常下修复任务，用户再验收——没有「退回哪段」的问题）。approve 也留痕（交付审计 + A5 纪要素材）。
- **「待确认」不落 PENDING 实体**：由条件推导（PRD 就绪未确认→需求端亮按钮；preview-ready→Demo 按钮；bug 清零→开发平台亮「开发完成」；开发完成通过→需求端亮「验收」），点击即落记录。与 A2 计算式待办天然吻合，`GATE_PENDING` 派生源改为期门就绪查询。
- **多账号是常态**：`account_id` 从第一天记；现在一个账号做完所有事只是注意力的临时集中，将来拆角色零迁移（A2 既定：owner 列已就位、角色过滤后置）。

## 4. 项目状态与需求池

- **项目状态**：「开发中 / 已交付」= 派生（有无 OPEN 期；二期开启自动翻回开发中——现实如此）；「归档」= 真实动作落 `prj_projects.archived_at`（**单向终点**）。v1 无暂停。DELETE 真删级联不变（B0）。项目列表过滤参数补 `archived`（A2 的 active/pending/all 之外）。
- **需求池**（项目级、随时可记的收件清单，原「下期需求池」措辞退役）：表 **`prj_demand_pool_entries`**（`project_id` · `content` · `kind?(REQUIREMENT|BUG)` · `source(用户|测试|验收)` · `created_by` · `created_at`，无状态列）。端点 `POST/GET /api/projects/{id}/demand-pool`。验收前后都能记、用户/测试都能提；**开新期时是需求梳理的输入**。驳回反馈**不自动入池**（归纪要/A5；入池是显式动作）。
- **期后修复不受期锁**：期已关时用户报 bug → 落需求池；开发平台可直接在工作区跑修复任务（工具项目级），bug 记录照常闭环（A4）。

## 5. API 与 SSE 面

- 门操作：`POST /api/projects/{id}/stage/approve`（无体）、`POST …/stage/reject` `{reason 必填}`；校验失败 409 `PRJ_`。
- 归档：`POST /api/projects/{id}/archive`（单向）。
- 需求池：`POST/GET /api/projects/{id}/demand-pool`。
- 项目详情返回：期位置（stage/标签）+ **主链定义数据**（阶段序列，前端按数据渲染进度条，过程演化 UI 少改）+ 门就绪 `gate: {actor, ready}`（计数门禁 ∧ 业务谓词，前端点亮按钮）+ 派生项目状态。
- SSE：`stage-changed` **保留**，驳回时 payload 增 `reason?`（前端展示驳回理由）；收口时照常发（stage=关闭），前端重拉 REST（ADR-0001）。**零新增事件名**。
- 「对话建项目」的问答 = A1 等待点通道（QUESTION）在需求端项目详情的呈现，与开发平台共用同一套 wait 端点，零新增机制。

## 7. 演化与雾（v1 明确不做）

- **二期开启动作**：开期端点（seq+1）+ ≥2 期 UI 才显示期（fog 既有「多期流程」项扩充）；v1 每项目 1 期。
- **严格产物门控**：产物齐全才放行（电商类严格过程）——v1 产物清单仅作沉淀范围；真需要时主链定义加 required 标志。
- **生产环境与运维服务**：平台基于项目的服务（隔离、带中间件、类沙盒的环境管理；Environment kind=prod）——「这块要做，平台早期用不上」；Phase B（托管上线既有出局项）。
