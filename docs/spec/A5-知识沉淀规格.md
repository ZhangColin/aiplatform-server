## 0. 总则

- **叙事点不缩水的兑现清单**：阶段产物（B0 片 3 已带入）之上，本票补齐问答纪要、验收反馈、测试报告 + Bug 三路摄取；「交付物清单」类**不单列**（A3 无交付段，收口审计素材已由 FEEDBACK / BUG 覆盖）。
- **摄取统一事件驱动**：素材来源落定的那一刻入库，幂等键 = `(kind, source_ref)`（删后插）；**不做 agent 总结纪要**（对话精华 = docs/06 二期既定）。
- **知识库只装「内容稳定且跨单有检索价值」的素材**：状态机终态的审计价值走关系表（`tsk_bugs` / `prj_confirmations`），不进向量库。
- 验收锚点：**第二单能命中第一单的 PRD / 纪要 / Bug**（§6）。

## 1. 五类素材与摄取挂钩

| kind | 素材 | 摄取挂钩（事件） | source_ref | chunk 形态 |
|---|---|---|---|---|
| `ARTIFACT` | 主链定义产物清单内的文档（v1 仅需求梳理段 `PRD.md`，见 §7） | 门 approve 编排处，读工作区文件分块 | `{projectId}:{stage}:{文件名}` | 分块（段落级 ~800 字符，实现定） |
| `QA` | 等待点 QUESTION 的 `body`（问题）+ `settle_outcome`（答复） | settle(Answer) 编排处即刻 | waitId | 单条 `问：…\n答：…`（格式实现定） |
| `FEEDBACK` | 确认留痕（`prj_confirmations`：门 kind / decision / reason） | confirmation 落库编排处 | confirmationId | 单条 `〔门·决策〕理由：…` |
| `TEST_REPORT` | 任务确认时 `submitted_payload.report`（首轮与复测任务同规则） | 任务 confirm 编排处 | taskId | 分块 |
| `BUG` | `tsk_bugs` 行（标题 / 描述 / 复现步骤 / 严重级） | 任务 confirm Bug 入库处，**仅 OPEN 时刻一次** | bugId | 单条（Bug 一条一块） |

- **幂等**：入库一律按 `(kind, source_ref)` 删后插——驳回重交再确认（同 taskId）、产物重入库，天然覆盖不重复。
- **摄取时点 = AFTER_COMMIT**（事务外；embedding 是外部调用，不进门操作事务）。失败**降级不炸**：记日志跳过，不阻断主流程；丢失容忍（重试端点不建，真痛再加）。
- **明确不入**：Bug 状态演化（FIXED/VERIFIED）、`fix_note`、复测逐条 results（终态审计走表）；需求池条目（显式动作、开新期输入）；素材上传物（v1 无上传通道）；初始需求原文（随 PRD 捕获，独立采集 = 对话精华二期）。

## 2. 存储模型（base.knowledge）

- 单表 **`knw_chunks`**（B0 片 3 定名落地）：`id` PK · `kind` · `source_ref` · `project_id` · `project_name` · `title` · `seq` · `chunk` · `embedding` · `meta` jsonb · `created_at`；索引 `(kind, source_ref)`（幂等删插）、`project_id`（级联清理）、HNSW 余弦（embedding）。
- **无资产表、无维度标签**（业务/技术/行业两维模型 = 演化，§7）；`meta` jsonb 留扩展位（stage / severity 等）。
- `KnowledgePort` 形态微扩（片 3 签名细化，实现片可再调）：

```java
// base.knowledge 对业务层的端口（application 层）
void index(KnowledgeSpec spec);                 // 幂等：(kind, sourceRef) 删后插
List<KnowledgeHit> retrieve(String query, int topK);
void purgeByProject(String projectId);          // 项目删除级联清理入口
record KnowledgeSpec(String kind, String sourceRef, String projectId, String projectName,
                     String title, List<String> chunks, Map<String, Object> meta)
record KnowledgeHit(String kind, String sourceProjectName, String title, String chunk)
```

## 3. 检索注入（注入点核对结论）

- **统一缝 = business.project 编排层 runTask 下发前**：所有 agent 任务（BA / Demo 自动段，DEV / ARCH 手动，A4 修复 run）单点检索注入——修复 run 经工作区任务下发端口复用片 5 编排（A4 §4），**自动获得注入 = 「测试阶段命中历史 Bug」的兑现点**。「每阶段开始检索注入」由此成立：阶段的首个任务即注入，同阶段后续任务也注入（超出叙事、不违背）。
- **策略：不过滤、全局跨项目、纯相似度**（demo 行为）——跨项目命中是特性（单租户内部平台，「越做越强」= 全局记忆）；类型配额是检索质量真出问题时的演化项（§7）。
- query = 任务 prompt 全文（超长截断，上限实现定）；**topK 默认 5**（demo 3，素材增类后上调；可配）。
- **不注入**：OPC 人工任务与复测（无 agent run）、权限答复（PERMISSION 等待点不摄取也不注入）。
- embedding 服务不可用：检索降级为空注入、不炸（B0 片 3 既定口径）。

## 4. 可见性与兑现

- **SSE `knowledge-retrieved` payload 扩展**：`projectId` `runId` `items`，items = `[{kind, 来源项目名, title, 片段?}]`——前端可呈现「本单命中第一单的 PRD」（清单正本已改）。
- **演示 / 调试端点 `GET /api/knowledge/search?q=&topK=`**（dev 视角）：验收 curl 复验命中用；将来管理后台知识库视图的消费缝。
- 项目沉淀列表端点 v1 **不做**（无消费方，管理后台生长点）。

## 5. 删除级联

- 项目 DELETE → `purgeByProject` 按 project_id 级联清 `knw_chunks`（补 demo docs/06 已知 TODO）；B0 §6 步骤 6 的清理范围随含 `knw_`。

## 6. 验收口径（本机 8888）

1. 第一单全流程走完（问答答复、门确认与驳回、测试任务确认 + Bug 入库）→ `knw_chunks` 五类各有行；
2. 建第二单（相似需求域）→ BA 自动 run 的 `knowledge-retrieved` items 含第一单 PRD / QA 命中项；
3. 第二单派发修复 run → `knowledge-retrieved` items 含第一单 BUG 命中项；
4. `GET /api/knowledge/search?q=` curl 复验；embedding 服务停机 → 入库 / 检索降级不炸。

## 7. 演化与雾（v1 明确不做）

- **Demo 产物是否沉淀**：v1 不入向量库——index.html 是项目产物的一部分（预览 / 源码包保留参考身份），但知识沉淀不做（docs/06「代码 ❌」+ demo ARTIFACTS 映射无 Demo 项双重佐证）；**要不要沉淀以后业务决定**。主链定义 Demo 段产物清单 v1 留空（A3 连带修订）。
- 维度标签（业务 / 技术 / 行业）与 skill 形态（两维模型，docs/06 Step 7+）。
- 对话精华（用户原始表达 → 澄清问题映射，docs/06 二期）与素材上传入库。
- 检索质量优化（类型配额 / 混合检索 / 重排）；项目沉淀列表端点（管理后台生长点）。
- 摄取重试端点与补偿（丢失容忍的代价，真痛再加）。

## 8. 落码归属

- `base.knowledge`：`knw_chunks` 表 + `KnowledgePort` 扩展（index 幂等 / retrieve / purgeByProject）。
- `business.project`：approve 编排挂 ARTIFACT 摄取；settle(Answer) 编排挂 QA；门操作挂 FEEDBACK；runTask 编排单点检索注入 + `knowledge-retrieved` 发射（payload 扩展）；search 端点。
- `business.task`：confirm 编排挂 TEST_REPORT + BUG 摄取。
- 实现完成后给 aiplatform-web 发对接 issue：命中条目展示（`knowledge-retrieved` items 渲染）。
