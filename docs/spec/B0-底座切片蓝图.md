## 1. 包结构定稿

**单 module、双分区**。Maven 不拆模块；依赖方向靠 ArchUnit 守护：**`base` 包不得 import `business` 包**（一条规则）。

```
com.aieducenter.aiplatform
├── base                    # 分区：基础设施能力层（端口-适配器），零业务概念
│   ├── workspace           # BC：环境抽象 + Docker 后端 + 中间件资源 + 工作区落库   [SUPPORTING]
│   ├── agentengine         # BC：智能体适配层 + 引擎注册 + agent 会话落库          [GENERIC]
│   ├── metering            # BC：计量——UsageEvent 落库 / 单价计价 / 按期聚合（A1 修订建） [SUPPORTING]
│   ├── chatagent           # BC：对话智能体内核（AgentScope HarnessAgent 进程内 + 事件/工作区/等待点双向桥 + PG 会话恢复，#48） [GENERIC]
│   ├── eventhub            # BC：SSE 技术事件广播（内存单实例起步）               [GENERIC]
│   ├── knowledge           # BC：知识入库/检索 + EmbeddingClient + pgvector        [SUPPORTING]
│   └── process             # BC：阶段推进引擎（序列/门禁/迁移），无表，状态由持有方保存 [SUPPORTING]
└── business                # 分区：交付业务（CORE 子域）
    ├── project             # BC：项目聚合 + 角色卡 preset + 主链总装（B0 建最小版）
    ├── identity            # BC：账号 + OIDC BFF 认证（A2 建：idn_accounts + /auth/* + /api/me） [SUPPORTING]
    ├── workbench           # BC：门户读模型查询聚合——待办列表（A2 建；无表无领域实体，纯查询侧） [SUPPORTING]
    ├── task                # BC：任务系统——测试外包循环 + Bug 三态（A4 建：tsk_tasks / tsk_bugs + 修复编排链） [CORE]
                              # 远期 BC：billing / asset / processconfig
```

- **分区 ≠ 限界上下文**。base/business 是架构标签（类比 domain/application 层名），BC 是区内每个包，各带 `package-info` + `@BoundedContext(subDomain=…)`，内部按 cartisan 规范四层（domain / application / infrastructure / endpoints）。
- 表前缀随 BC：`wsp_` / `agt_` / `knw_` / `prj_` / `cat_`（cartisan 表命名规范：同一上下文同前缀）。

**demo → 重写的两个关键拆解**（「底座零业务概念」的落地）：

| demo 现状 | 重写归属 | 理由 |
|---|---|---|
| `Role` 角色卡（enum 硬编码 systemPrompt + modelId）长在 agent 包 | **business.project**（代码配置起步，不落库） | docs/11：「业务智能体 MVP 用 agent preset」；`CodingAgentAdapter.runTask` 以 systemPrompt/modelId 为**入参**，适配层不含任何角色概念 |
| `Project` 聚合（业务字段+环境句柄+stage 混在一起）、`ProjectController` 是全局汇聚点 | **business.project**（聚合+主链 Controller）；环境句柄部分归 **base.workspace**（`wsp_workspaces` 落库，重启接回） | demo 的 `create` = 建工作区+落库+发事件，本质是业务编排；底座只管工作区生命周期 |
| 阶段→产物文件名映射（BA→PRD.md）在 KnowledgeService | **business.project** 调 `KnowledgePort` 时传内容+元数据 | 「哪个阶段产出什么文件」是业务知识 |
| Stage 状态机内嵌在 ProjectController.approve() | **base.process** 独立引擎类，无表；阶段序列（平台主链定义，A3：无模板概念）由业务侧传入 | docs/11：「Stage 状态机 = 流程引擎基础设施，业务期状态机映射其上」（A3 票） |

## 3. 弱化实现与演化升级方向

| 现状（Phase A 弱化版） | 触发信号 | 升级路径（参考出处） |
|---|---|---|
| docker CLI 子进程（ProcessBuilder） | 上云 / 多机（Phase B） | `EnvironmentBackend` 端口缝新增 TKE/远端适配器，配置切换（demo `EnvironmentConfig` 已预留） |
| SSE 内存单实例、重启丢事件 | 多实例部署 / 事件可靠性要求 | 事件持久化（`agent_run_events`，`{runId}:{seq}` 复合 ID）先于广播 + Last-Event-ID 断线补发；CC `docs/design/04` §4.6、`EventReplayService.java` 有实现参考 |
| JdbcTemplate + pgvector | 数据量 / 检索质量需求 | `KnowledgePort` 换腾讯云向量库（>100 万向量才迁，MVP 不引入既定）；fog 已记 embedding 生产形态 |
| 角色卡代码配置 | 角色多了要运营管理 | preset 落库（可热更新，CC `agent_roles` 表参考）+ **模型档位路由**：角色卡存档位（reasoning/coding/fast）不存模型名，`llm_providers.model_tiers` 做映射，换模型不动角色卡（CC `docs/design/07` §7.2） |
| agent 会话最小落库 | 多副本 / 高可用 | 会话与运行状态外置存储（CC 用 PG AgentStateStore 多副本就绪） |
| 单体同进程 | 规模到了要拆服务 | 端口即边界，换 REST/消息实现，业务域不动（docs/11 既定） |

## 5. 验收口径总则

1. **对照对象是本服务自己**，不是 demo——demo 的唯一用途是实现时查它怎么解决的，不对拍。
2. **副作用以真实状态为准**（文件 / git / DB / 容器存活），不以事件自述为准。
3. 未实测的假设（第三方库行为、CLI 输出格式、超时语义等）**全部进 PoC 清单**：每个 ≤半天可验证，且预写备选方案。
4. cartisan 测试规范照常执行（领域层 95%+ / 应用层 90%+ / 基础设施 80%+；`given_when_then` 命名）。
5. 单片验收 = 该片 REST/SSE 端点手动 curl 可用 + 测试过；全链路验收 = 片 5 完成时走 §6。

## 6. 全链路五步冒烟 checklist（片 5 验收）

前置：`GET /api/events` SSE 长连接已建立；本机 Docker daemon、平台 PG（含 vector 扩展）、Redis、embedding 服务（:9091）就绪。

| # | 步骤 | 动作 | 通过标准（看真实状态） |
|---|---|---|---|
| 1 | 建项目 | `POST /api/projects`（选引擎） | dev 容器 + 项目专属 pg/redis 容器存活；`/workspace/.env` 已写入连接串；`wsp_*`/`prj_projects` 落库；SSE `workspace-created` + `stage-changed`(BA) |
| 2 | 下任务 | `POST /api/projects/{id}/agent/task` | SSE 依次 `role-assigned` →（`knowledge-retrieved`）→ `task-start` → `session-created` → part 事件流 → `task-finish`；`agt_agent_sessions` 落库；taskCount=1 |
| 3 | HITL | `GET …/agent/questions` → `POST …/agent/questions/reply`；`POST …/agent/permission` | agent 收到答复继续跑完；权限拒绝不形成审批循环 |
| 4 | 预览 | `GET /api/projects/{id}/preview` | 返回可访问的 localhost 预览 URL；SSE `preview-ready` |
| 5 | 审批流转 | `POST …/stage/approve`（至验收门） | 每门：taskCount≥1 才放行（验收门 = 0）；本阶段产物分块入 `knw_*` 且 embedding 就位；stage 推进、SSE `stage-changed`；门不足 409；驳回停留（带 reason）；**验收门通过即收口：期 CLOSED、项目已交付**（A3：无交付段） |
| 6 | 收尾 | `DELETE /api/projects/{id}` | 容器/网络/卷级联清理；三区表记录删除；SSE `workspace-destroyed` |

（步骤编号沿用五步口径，「收尾」为顺带验证。）
