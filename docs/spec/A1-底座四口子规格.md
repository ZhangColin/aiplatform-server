## 0. 总则

- 四口子 = docs/11 §7 既定的底座全部新增通道（**只此四个，不加业务概念**）：① HITL 等待点通道；② 计量埋点；③ 任务完成回填；④ 环境生命周期钩子。
- **③ 不是独立端口**：它是 ① 的引用语义 + 业务层编排约定（§3）。
- **base 新增第六 BC `base.metering`**（B0 §1 修订，五→六）：计量上下文平台内起步——决策「以自用为主、适当通用，以后迁出独立服务 = 适配器轻量切换」，修订 docs/11 §8「独立服务」前提（独立薄服务降为演化方向）。
- 事件协作统一走 cartisan **应用事件**（`ApplicationEvent` + `ApplicationEventPublisher` PUBLISHER 端口，AFTER_COMMIT 分发，进程内 Spring 实现起步）；**聚合领域事件已废弃不用**（实践结论：收益小复杂度高）。SSE 呈现通道归属不变（ADR-0001：业务编排层发射，base 不发 SSE）。
- 落位：①② → 片 2（agentengine + metering）；④ 发布端 → 片 1（workspace）；③ 编排 → 片 5 / A4 业务侧。

## 1. 口子①：HITL 等待点通道

### 1.1 模型：统一等待点

底座内以统一「等待点（Wait Point）」实体承载两类挂起：问答（QUESTION）与权限（PERMISSION）。**adapter 对引擎的方法名不动**（B0 片 2 已定：pendingQuestions / replyQuestions / replyPermission / health）；统一模型是 agentengine 对业务层暴露的形态——demo 病「权限请求无发现通道、问答重启后看得见答不了」由此补齐。

```java
// base.agentengine 对业务层的端口（application 层）
List<WaitPoint> pendingWaits(WorkspaceId workspaceId);   // 跨会话聚合
Optional<WaitPoint> wait(String waitId);
void settle(WaitSettlement settlement);                  // 非 PENDING/不可续跑 → WaitConflictException → 409

record WaitPoint(String waitId, WaitKind kind, String runId, String sessionId,
                 WorkspaceId workspaceId, WaitStatus status, Instant raisedAt,
                 Map<String, Object> body);              // body = 引擎载荷原样，底座不解释
enum WaitKind { QUESTION, PERMISSION }
enum WaitStatus { PENDING, SETTLED, EXPIRED, CANCELLED } // settle 结果另存 settle_outcome

sealed interface WaitSettlement permits Answer, PermissionDecision, Deferred { String waitId(); }
record Answer(String waitId, List<List<String>> answers) implements WaitSettlement;        // 问答（选项 label）
record PermissionDecision(String waitId, boolean approve) implements WaitSettlement;       // 权限
record Deferred(String waitId, String note) implements WaitSettlement;                     // 「已转任务」关闭等待点（③）
```

- 落库 **`agt_pending_waits`**（wait_id PK · workspace_id · session_id · run_id · kind · status · body jsonb · raised_at · settled_at · settle_outcome）——**中性寻址，无 projectId**；跨重启存活。
- `waitId` 稳定标识 = ③ 回填的引用键；业务层透传存储，底座不解释。

### 1.2 runTask 扩展（续跑缝 + 计量透传）

```java
record AgentTaskCommand(
    String runId,               // 任务端点（业务编排层）生成（ADR-0001），底座透传
    String prompt,
    String systemPrompt,        // 角色卡入参（B0 既定：底座无角色概念）
    String modelId,
    String sessionId,           // 可空：非空 = 复用既有会话（续跑缝，③ 用）
    UsageContext usageContext); // 可空：计量归属（§2.4），底座透传不解释

RunResult runTask(WorkspaceHandle handle, AgentTaskCommand command, Consumer<AgentEvent> sink);
record RunResult(String runId, String sessionId, boolean accepted);
```

### 1.3 答复语义（CC 避雷清单落点）

| CC 实测避雷 | 对策（Phase A 从简） |
|---|---|
| 拒绝后 LLM 换形式重试 → 审批循环 | 同 run 内 permission deny 计数 ≥3（可配）→ 平台终止运行 + 记日志 |
| 工具超时/崩溃留 ASKING 死状态，后续任务全卡 | run 终态（finish/error/timeout/cancel）联动其 PENDING 等待点 → EXPIRED；**复用会话下发前校验无残留**，有则先清理再跑 |
| 陈旧等待点批准 → 非法跳变（闸门同类） | settle 前校验 status=PENDING 且会话可续跑，否则 409 |
| 权限上下文随会话持久化，变更不生效 | 权限配置 = 环境初始化注入（片 1/2 现状）；存量会话粘性进 PoC 清单（§5） |
| 恢复是否真执行要看真实副作用 | 验收口径总则沿用 B0 §5.2（副作用以文件/git/DB 为准） |

### 1.4 SSE 事件（治理：进 [SSE 清单](SSE事件清单.md) 再上线，已改）

| type | payload 字段 | 说明 |
|---|---|---|
| `wait-raised`（新增） | `projectId` `runId` `waitId` `kind` `summary` | 等待点落库即发；summary = 适配器从引擎载荷提取的中性短文本 |
| `wait-settled`（替换 `questions-answered` / `permission-replied`） | `projectId` `runId` `waitId` `outcome` | outcome = answered / approved / denied / deferred |

projectId 由业务编排层桥接注入（ADR-0001 编排层发射制不变）；事件丢失可接受，REST 重查兜底。

### 1.5 引擎能力矩阵

| 引擎 | 问答 | 权限 | 说明 |
|---|---|---|---|
| opencode | ✅ | ✅ | 片 2 全实现（容器内 serve 的 question/permissions 端点） |
| dsh（headless） | ✗ | ✗ | `pendingQuestions` 恒空、reply no-op，如实暴露；DSH 服务化（web profile HTTP+SSE）为既定缝，不进 Phase A（ADR-0004 既定 defer） |

## 2. 口子②：计量埋点

### 2.1 base.metering（新 BC，错误码前缀用 ADR-0001 已预留的 `METER_`）

平台内计量上下文：**零业务概念（subject 不透明）、零钱概念（只记 token）**。

```java
// CLIENT 端口（直调，非应用事件——上报要幂等/重试语义，ADR-0001「计量走直调上报」维持）
public interface UsageEventSink { void report(UsageEvent event); }    // eventId 幂等
public interface UsageQueryPort {
    UsageSummary bySubject(String subject, Instant from, Instant to); // 按 subject 聚合（分模型/维度）
}
```

- 表 **`met_usage_events`**（event_id PK 幂等键 · ts · subject · run_id · session_id · provider · model · engine · dims jsonb · input · output · cache_read · cache_write · reasoning）。
- **迁出独立服务 = sink / query 适配器换 REST，业务域与 agentengine 不动**（端口即边界，B0 §3 同构）；时点与计价归 [A6 票](https://github.com/ZhangColin/aiplatform-server/issues/12)。

### 2.2 UsageEvent 协议（研究稿 F4.2 照收）

```java
record UsageEvent(String eventId, Instant ts,
                  String subject,                              // 不透明归属 id（业务层传 projectId）
                  String runId, String sessionId,
                  String provider, String model, String engine,
                  Map<String, String> dims,                    // role/stage 等业务维度，底座透传
                  TokenUsage tokens)
record TokenUsage(long input, long output, long cacheRead, long cacheWrite, long reasoning)
```

口径：**五档分列**（三家 API 归一化：OpenAI prompt / Anthropic input+cache 两类 / DeepSeek hit+miss → input/output/cache_read/cache_write/reasoning），只记 token 不记钱。

### 2.3 粒度与埋点落位（demo 六处 → 新结构；demo 侧全部未实现，无迁移包袱）

**run 级一条**——`step-finish` 增量求和是 adapter 内部实现，不进协议（OpenCode 无总用量字段、tokens 为每步增量，求和归 OpenCodeAdapter）。

| demo 六处（文档清单） | 重写落位 |
|---|---|
| `CodingAgentAdapter.getUsage`（ADR-0001 预留未实现） | 不恢复独立方法：求和在 adapter 内部，run 结束即上报 |
| `AgentController.task()` 上下文组装 | **business.project 编排处**组装 `UsageContext` 随 AgentTaskCommand 传入（demo 该职责归业务层，B0 §1 拆解既定） |
| `OpenCodeAdapter` step-finish 求和 | OpenCodeAdapter 内部（片 2） |
| `DshAdapter` | headless 无 usage：**不发 UsageEvent**（无数据不造数）；dims 预留 `source=estimated` 标注，DSH 服务化后补 |
| `AgentEvent` + `EventHub` | 不走 SSE；UsageEventSink 直调 base.metering |
| `AgentModelConfig` | base.agentengine 配置类（provider/model 默认值），填入 UsageEvent；不进口子清单 |

### 2.4 UsageContext 透传

```java
record UsageContext(String subject, Map<String, String> dims);  // subject = projectId（业务层定），底座不解释
```

### 2.5 Phase A 查询面

业务层端点 **`GET /api/projects/{id}/usage`** → `UsageQueryPort`：总量 + 分模型/分角色聚合（地图终点「token 用量可见」）。度量单位 token——金额（平台成本）与按期聚合由 [A6](A6-计量计价与迁出规格.md) 扩展（`UsageSummary` 加 cost + `dims.iterationId` 透传）。

## 3. 口子③：任务完成回填（① 的引用 + 业务编排，不开新底座端口）

### 3.1 机制（三步）

1. 等待点出现 → 人选「转任务」→ 业务层 `settle(Deferred(waitId))` 关闭等待点 + 建任务（任务记录存 `waitId` **不透明引用**，底座不知道任务存在）；
2. OPC 完成 → 开发平台确认 → task 应用层发 **`TaskCompleted` 应用事件**（cartisan PUBLISHER 端口，AFTER_COMMIT）；
3. project 应用层监听（**唯一流程反应者**，docs/11 §7：task/billing 只发布不编排）→ 任务带 waitId 则 `runTask` **复用原 sessionId**、prompt = 任务结果（测试报告 + Bug 清单）——**续跑 = 给会话的新消息，不是问答答复**（demo replyQuestions 只收选项 label，装不下任务结果）。

### 3.2 陈旧防护

- settle 校验：见 §1.3（409）。
- 续跑前校验会话存在且可续跑（agentengine 会话表）；环境/会话已亡 → **记日志跳过，不抛**（回填幂等友好）。
- TaskCompleted 监听器幂等：以任务状态机守门（已确认/已取消的任务不再触发）。

## 4. 口子④：环境生命周期钩子

### 4.1 事件定义（cartisan 应用事件，中性载荷）

```java
record WorkspaceCreated(String eventId, Instant occurredAt, WorkspaceId workspaceId, EnvKind kind);
record WorkspaceDestroyed(String eventId, Instant occurredAt, WorkspaceId workspaceId);
record PreviewReady(String eventId, Instant occurredAt, WorkspaceId workspaceId, URI url);
```

- base.workspace **application 层**在副作用真实落定后经 PUBLISHER 端口发布；workspaceId 寻址，**无 projectId**（订阅方自行映射）。
  - **修订（#61，置备异步化）**：`WorkspaceCreated` 的「副作用」= 工作区记录（PROVISIONING 态）落库——创建即发射、容器后台置备中（不再是容器就绪）；`WorkspaceDestroyed`/`PreviewReady` 仍为真实副作用落定后发布。
- **Phase A 发布端就位**（SpringApplicationEventPublisher，一行 publish；无订阅方照发、测试可断言）——原则：需要事件协作的地方**设计好而不是回避**（部分旧决策考虑不全处以必要和合理为准）；**管道设施（outbox/事件存储/重放）一概不建**。
- SSE 平台通知不变：business 编排层发射（含 projectId）——**应用事件（协作）与 SSE（呈现）两机制不混**（ADR-0001）。

### 4.2 升级路径

第一个真实订阅方（fog：环境闲置回收——base 定时回收通知 business）/ 跨服务 → 换 `RabbitMQApplicationEventPublisher`（框架既有），**事件定义不动**。

## 5. 验收口径与 PoC 清单

各片验收在 B0 §5/§6 基础上追加：

- **片 1**：生命周期三事件被测试监听器捕获（AFTER_COMMIT 语义）。
- **片 2**：等待点落库；waitId 跨重启稳定；deny cap 触发终止；run 终态联动 EXPIRED；复用 sessionId 续跑成功；run 级 UsageEvent 一条入 `met_usage_events`（opencode）；DSH 无事件。
- **片 5 / A4**：转任务 → TaskCompleted → 续跑全链路；陈旧回填被跳过并记日志。

**PoC 清单**（B0 §5.3 纪律：各 ≤半天，预写备选）：

| 未实测假设 | 验证方式 | 备选 |
|---|---|---|
| OpenCode 权限配置注入对存量会话生效 | 改配置后旧会话行为 | 每次运行显式注入配置 |
| OpenCode 复用 session 发消息可续上下文 | 同 session 两轮消息上下文保持 | 结果拼入新 prompt 开新会话 |
| AFTER_COMMIT 发布对 SSE 时序无影响 | 片 1 集成测试 | 副作用落定后同步直调 |
