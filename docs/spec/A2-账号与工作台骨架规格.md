## 1. 范围与边界

**做**：`business.identity`（OIDC BFF 认证 + accounts 自动建档）+ `business.workbench`（计算式待办 + 门户读聚合）+ `prj_projects` 归属列 + 回调参数定稿（#8 输入）。

**不做**：任务 API（A4）、主链期状态机（A3）、角色列与权限谓词（拆角色票，模型见 docs/11 §5）、成员页（同前）、任何推送（邮件/微信出局）。

## 2. OIDC 登录（BFF 形态，照 demo 实现）

流程照 [调研文档](../research/identity-integration.md) §1.2 时序（demo 逐条对应表 §1.3），此处只记**决议与差异**：

| # | 事项 | 决议 |
|---|---|---|
| 1 | 端点 | `GET /auth/login`、`GET /auth/callback`、`POST /auth/logout`、`GET /api/me`，照 demo |
| 2 | 会话存储 | **内存 Map**（BFF 自管）。cookie：`aiplatform_session`（不透明 sessionId，HttpOnly + SameSite=Lax，无 maxAge）+ `oauth_txn`（`state:nonce`，maxAge 600s）。token 三件套只存服务端。重启即丢 = 一次 SSO 弹回重登（identity 侧 SSO 会话仍在，不输密码）。升级触发：多实例部署 / 会话跨重启成为硬需求 → PG 表 `idn_sessions` 换 store 实现，cookie 契约不动 |
| 3 | id_token 验签 | **第一天就做**：拉 `/jwks` 缓存 + RS256 验签 + 校验 `iss`/`aud`(=clientId)/`exp`/`nonce`（nimbus-jose-jwt）。理由：尽早真集成，逼出 identity 侧问题（已兑现一处，见 §7） |
| 4 | 本地固定账号 | **不做 stub profile**（identity 本机常启；避免前后端特殊代码）。冒烟认证走 `scripts/login.sh`：curl cookie-jar 走完 /auth/login → identity `/api/sso/login`（密码）→ 回调链，产出 jar 供 `curl -b` 用。前提：identity 侧一个测试账号（凭据本地 env，不进仓库）。MockMvc 契约测试不走此路——测试夹具直接注 RequestContext |
| 5 | 会话内容 | `id_token`（/api/me 解 claims + 登出 hint）、`access_token`（v1 不用）、`refresh_token`（v1 不用）、`expiresAt`、`accountId`（callback 建档时映射，每请求免查库） |
| 6 | RequestContext | 自写小 filter（ADR-0001）：cookie → 会话 → `userId = accountId`（内部 PK，非 sub）、`userName = 显示名` |
| 7 | 配置 | `sso.*` 七项照 demo `SsoProperties`；`issuer` 值待 #8 与 identity 定稿（§7）。凭据（clientId/clientSecret）只落本地不入库配置（`.env*.local` / `application-local.yml`），**不进 issue/spec/git** |
| 8 | 本地纪律 | ① 全程 `localhost`，禁混 `127.0.0.1`（不同 host：cookie 带不过、白名单精确匹配炸）；② `sso.cookie-secure=false`（http 下 Safari/Firefox 拒存 Secure cookie，demo 踩过）；③ cookie 名独一（`aiplatform_session`/`oauth_txn`） |

## 3. accounts 最小版（business.identity）

- **表 `idn_accounts`**：`id` PK、`external_id`（= OIDC `sub`，唯一索引）、`display_name`、审计字段。**无 issuer 列**（v1 单 IdP，多 IdP 进雾）、**无角色列**（拆角色票加）。
- **建档**：callback 换 token 成功后 upsert——按 `external_id` 找，无则建，显示名有变则更新；`/api/me` 纯读（claims 从会话 id_token 解）。
- **display_name 取值**：`nickname` → `name` → `preferred_username` → `sub` 兜底。
- **`/api/me` 响应**：`{ accountId, displayName }`（最小；email/picture 不进 v1 契约）。
- **归属列**：`prj_projects` 加 `owner_account_id`（创建时填，读路径 v1 不过滤——拆角色票零迁移直接用）；`task.assignee` 留给 A4 建表同理处理。
- **错误码前缀**：`IDN_`（ADR-0001 已预留）。

## 4. 待办模型（计算式，无表）

**概念**：待办 = 需要人处理的事项列表，是**各处已有状态的实时投影**，非独立实体；v1 无信息性通知流（docs/11「通知」一词废弃，词条见 CONTEXT.md「待办」）。

| type | 视角 | 源（投影自） | 接线 |
|---|---|---|---|
| `AGENT_WAIT`（智能体等待答复） | dev | `agt_pending_waits`（pending 态） | **A2** |
| `GATE_PENDING`（门待拍板） | dev | `prj_iterations`（期处于门 ∧ 门禁满足；[A3 票 #9](https://github.com/ZhangColin/aiplatform-server/issues/9) 修订：状态机在期） | **A2** |
| `TASK_SUBMITTED`（任务待确认） | dev | task BC（已提交态） | A4 |
| `RETEST_READY`（可发复测） | dev | task+bug 派生（存在已修复待复测 Bug ∧ 无进行中测试任务 ∧ 无 in-flight 修复——[A4 票 #10](https://github.com/ZhangColin/aiplatform-server/issues/10) 澄清修订） | A4 |
| `NEW_TASK`（新任务） | opc | task BC（指派给我） | A4 |
| `TASK_REJECTED`（被驳回） | opc | task BC（驳回退回） | A4 |

- **SSE 零新增**：前端收到既有平台通知（`wait-raised`/`stage-changed`/任务事件）即重拉待办——「事件让 UI 活，正确性走 REST」（ADR-0001）。
- **落库收件箱否决理由**：v1 无推送，收件箱表只买来双写一致性问题 + 完结状态机；源状态即真相。

## 5. business.workbench BC

- **定位**：SUPPORTING 子域、**查询侧聚合**（无表、无领域实体，纯 application + endpoints；package-info 写明）。
- **依赖**（查询端口，均为小扩展，随 A2 实现票落码）：base.agentengine 加跨项目 pending 等待点查询（`listPendingWaits()`）；business.project 加门就绪查询（`listGateReady()`）；A4 后接 task 查询端口。
- **API**：
  - `GET /api/todos?view=dev|opc`（默认 dev）→ `ApiResponse<List<TodoItem>>`，不分页（量小）。`TodoItem { type, projectId, refId, title, createdAt }`——`refId`：AGENT_WAIT=waitId、GATE_PENDING/RETEST_READY=projectId、任务型=taskId。
  - `GET /api/projects` 增状态过滤参数（project BC 自身演进，非 workbench）：`active`（进行中）、`pending`（存在任一 dev 待办的项目）、缺省 all。
- 无自有错误码前缀（查询聚合，错误来自源上下文）。

## 6. 三工作台 API 面（v1 最小集）与鉴权

| 工作台 | v1 API 面 |
|---|---|
| 需求端 | **零新增**——全复用 B0 片 5 端点（projects / agent task / questions / permission / preview / stage / delete） |
| 开发平台 | 片 5 端点 + `GET /api/todos?view=dev` + 项目列表状态过滤参数 |
| 任务平台 | auth 四端点 + `GET /api/todos?view=opc`；任务 API 全归 A4，前端只有骨架壳 |

**鉴权拦截面**：全 `/api/**` 拦截（含 SSE 双通道——EventSource 同源代理自动带 cookie），无会话 401。白名单：`/auth/**`、`/v3/api-docs/**`、`/swagger-ui/**`、actuator health。401/403 全局映射随片 0（ADR-0001）。

## 7. 域名与回调（#8 输入）

**提交给 identity/app-registry 对账的定稿值**：

- `redirect_uri = http://localhost:3333/auth/callback`（**前端 origin**，Next 代理到 8888——注册 8888 是错的：cookie 会落在 8888 host，前端 fetch 带不上）
- `post_logout_redirect_uri = http://localhost:3333/`
- scopes：`openid profile email`；grants：`authorization_code refresh_token`；展示名：AI 开发平台
- client 凭据已由 app-registry 发放，值存本地配置（不复述）

**待 identity 定稿的问题（本票调研发现）**：本机 :10001 discovery 自述 `issuer = https://identity.aieducenter.com`，该域名公网不可解析（对照组正常）——浏览器授权流程会 302 到死域名，JWKS 的 iss 校验也必挂。**建议**：本机实例照 identity 自己的 demo 用自洽 issuer（如 `http://identity.localhost:10001`）；生产再切公网域名。

**cookie 隔离背景**（备查）：浏览器 cookie 按 host 隔离、不按 port——裸 localhost 上所有服务共享一个 jar，撞名（`JSESSIONID` 类）是低概率难排障坑；identity 起独立 host（`identity.localhost`）= 结构性消灭；我方前后端 `localhost:3333/8888` 同 host 共享 jar 是 BFF 机制所需，不是风险。

## 8. 升级路径（演化注记）

- 会话：内存 → `idn_sessions` PG 表（多实例 / 跨重启硬需求时）
- 角色：accounts 加角色列 + 两谓词（docs/11 §5 模型已定），`owner_account_id` 已就位；Code-Canvas 授权矩阵实践（服务端切面强制）见 B0 §4②
- 生产：每环境一份 `sso.*`（issuer/redirectUri 随环境注册、`cookie-secure` 翻 true）；域名惯例同根域每服务一子域（`app.`/`identity.`…）——便利项非机制要求，OIDC 本就跨域设计
