# 本机依赖启动（dev 环境）

> dev 环境约定（地图 #1 Notes）：一台 Mac 手动起服务。端口分配——本服务 **8888** ·
> 前端 3333 · app-registry 8088 · identity 10001 · 平台 PG **5434** · Redis **6380** ·
> embedding **9091**。

## 一条命令起数据面（平台 PG + Redis）

```bash
docker compose -f docker-compose.dev.yml up -d
# PG：aiplatform / aiplatform / aiplatform-dev @ 5434（pgvector/pgvector:pg16，内置 vector 扩展）
# Redis：6380（本机 6379 已被他人带密码的实例占用，不共用）
```

PG 端口为什么不复用本机已有的：

| 端口 | 是什么 | 能否共用 |
|---|---|---|
| 5432 | 共享 aieducenter 库（Homebrew PG 18，无 pgvector） | 否——无 vector 扩展，且与其他业务库混放 |
| 5433 | 冻结 demo（deepseek-harness）的库 | 否——demo 是参考基准，不动它 |
| 5434 | **本服务平台 PG**（pgvector/pgvector:pg16） | 是 |

数据卷 `pgdata` 持久化；要重来就 `docker compose -f docker-compose.dev.yml down -v`
后重建空库（Flyway 会从 V1 重新跑）。

## embedding 服务（9091，片3 知识库依赖）

本机 fastembed（BAAI/bge-small-zh-v1.5，512 维）。极简服务脚本已收进本仓库
`scripts/embedding_server.py`（零框架依赖，接口 `POST /embed {"texts":[...]} → {"vectors":[[...]]}`）：

```bash
uv run --with fastembed python scripts/embedding_server.py
curl localhost:9091/health                            # → {"ok":true}
```

网络连不上 HuggingFace 时（fastembed 走 hf-xet 传输，对直连环境常见超时），可用
hf-mirror 手工预置模型缓存后离线启动（fastembed 默认缓存在 `/tmp/fastembed_cache`，
ONNX 在 Qdrant 镜像仓库）：

```bash
BASE=/tmp/fastembed_cache/models--Qdrant--bge-small-zh-v1.5
SHA=$(curl -s https://hf-mirror.com/api/models/Qdrant/bge-small-zh-v1.5 \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["sha"])')
mkdir -p $BASE/snapshots/$SHA $BASE/refs && echo $SHA > $BASE/refs/main
cd $BASE/snapshots/$SHA
for f in config.json tokenizer.json tokenizer_config.json special_tokens_map.json model_optimized.onnx; do
  curl -L -O "https://hf-mirror.com/Qdrant/bge-small-zh-v1.5/resolve/main/$f"
done
# 之后带 HF_HUB_OFFLINE=1 启动（从缓存离线加载，不碰 HF）
```

注意：`mvn test` 的知识语义命中测试（`KnowledgePortSemanticTest`）需要本服务在跑——
没起时该测试跳过（不失败），其余测试只依赖 PG。
