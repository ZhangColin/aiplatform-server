# 本机依赖启动（dev 环境）

> dev 环境约定（地图 #1 Notes）：一台 Mac 手动起服务。端口分配——本服务 **8888** ·
> 前端 3333 · app-registry 8088 · identity 10001 · 平台 PG **5434** · Redis **6380** ·
> embedding **9091**。

## 一条命令起数据面（平台 PG + Redis）

```bash
docker compose -f docker-compose.dev.yml up -d
# PG：aiplatform / aiplatform / aiplatform-dev @ 5434（pgvector/pgvector:pg16，内置 vector 扩展）
# Redis：6380（本机 6379 已被他人带密码的实例占用，不共用）
```

PG 端口为什么不复用本机已有的：

| 端口 | 是什么 | 能否共用 |
|---|---|---|
| 5432 | 共享 aieducenter 库（Homebrew PG 18，无 pgvector） | 否——无 vector 扩展，且与其他业务库混放 |
| 5433 | 冻结 demo（deepseek-harness）的库 | 否——demo 是参考基准，不动它 |
| 5434 | **本服务平台 PG**（pgvector/pgvector:pg16） | 是 |

数据卷 `pgdata` 持久化；要重来就 `docker compose -f docker-compose.dev.yml down -v`
后重建空库（Flyway 会从 V1 重新跑）。

## embedding 服务（9091，片3 知识库依赖）

本机 fastembed（BAAI/bge-small-zh-v1.5，512 维）。Phase A 直接用 demo 的极简服务
（零框架依赖，接口 `POST /embed {"texts":[...]} → {"vectors":[[...]]}`）：

```bash
cd ~/workspace/aiplatform/deepseek-harness/platform/embed
uv run --with fastembed python embedding_server.py   # 或 .venv/bin/python embedding_server.py
curl localhost:9091/health                            # → {"ok":true}
```

片3 落 `EmbeddingClient` 时再决定是否把脚本收进本仓库。

## 起服务与验收

```bash
mvn spring-boot:run        # 默认 local profile → 5434/aiplatform
curl localhost:8888/actuator/health
```
