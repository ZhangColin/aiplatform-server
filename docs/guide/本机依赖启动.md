# 本机依赖启动（dev 环境）

> dev 环境约定（地图 #1 Notes）：一台 Mac 手动起服务。端口分配——本服务 **8888** ·
> 前端 3333 · app-registry 8088 · identity 10001 · 平台 PG **5434** · Redis **6380** ·
> embedding **9091**。

## 一条命令起数据面（平台 PG + Redis）

```bash
docker compose -f docker-compose.dev.yml up -d
# PG：aiplatform / aiplatform / aiplatform-dev @ 5434（pgvector/pgvector:pg16，内置 vector 扩展）
# Redis：6380（本机 6379 已被他人带密码的实例占用，不共用）
```

PG 端口为什么不复用本机已有的：

| 端口 | 是什么 | 能否共用 |
|---|---|---|
| 5432 | 共享 aieducenter 库（Homebrew PG 18，无 pgvector） | 否——无 vector 扩展，且与其他业务库混放 |
| 5433 | 冻结 demo（deepseek-harness）的库 | 否——demo 是参考基准，不动它 |
| 5434 | **本服务平台 PG**（pgvector/pgvector:pg16） | 是 |

数据卷 `pgdata` 持久化；要重来就 `docker compose -f docker-compose.dev.yml down -v`
后重建空库（Flyway 会从 V1 重新跑）。

## embedding 服务（9091，片3 知识库依赖）

本机 fastembed（BAAI/bge-small-zh-v1.5，512 维）。极简服务脚本已收进本仓库
`scripts/embedding_server.py`（零框架依赖，接口 `POST /embed {"texts":[...]} → {"vectors":[[...]]}`）：

```bash
uv run --with fastembed python scripts/embedding_server.py
curl localhost:9091/health                            # → {"ok":true}
```

网络连不上 HuggingFace 时（fastembed 走 hf-xet 传输，对直连环境常见超时），可用
hf-mirror 手工预置模型缓存后离线启动（fastembed 默认缓存在 `/tmp/fastembed_cache`，
ONNX 在 Qdrant 镜像仓库）：

```bash
BASE=/tmp/fastembed_cache/models--Qdrant--bge-small-zh-v1.5
SHA=$(curl -s https://hf-mirror.com/api/models/Qdrant/bge-small-zh-v1.5 \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["sha"])')
mkdir -p $BASE/snapshots/$SHA $BASE/refs && echo $SHA > $BASE/refs/main
cd $BASE/snapshots/$SHA
for f in config.json tokenizer.json tokenizer_config.json special_tokens_map.json model_optimized.onnx; do
  curl -L -O "https://hf-mirror.com/Qdrant/bge-small-zh-v1.5/resolve/main/$f"
done
# 之后带 HF_HUB_OFFLINE=1 启动（从缓存离线加载，不碰 HF）
```

注意：`mvn test` 的知识语义命中测试（`KnowledgePortSemanticTest`）需要本服务在跑——
没起时该测试跳过（不失败），其余测试只依赖 PG。

## A2 登录联调（identity OIDC + BFF）

认证走 identity 服务（`identity.localhost:10001`）授权码模式，本服务 BFF 三端点
（`/auth/login`、`/auth/callback`、`/auth/logout`）+ `/api/me`。本地纪律：**全程
`localhost`，禁混 `127.0.0.1`**（cookie 按域隔离不分端口，host 不一致 cookie 带不过、
identity 白名单精确匹配会炸）；`sso.cookie-secure=false`（http 下 Safari/Firefox
拒存 Secure cookie）。

**凭据只落本地，不进 git**：仓库根建 `.env.local`（已 gitignore）：

```bash
# .env.local（示例，勿提交）
SSO_CLIENT_ID=<app-registry 发放的 client_id>
SSO_CLIENT_SECRET=<app-registry 一次性发放的 client_secret>
SSO_ACCOUNT=<identity 测试账号 email>
SSO_PASSWORD=<identity 测试账号密码>
```

起服务（local profile 默认值已在 application.yml，issuer/redirect-uri 无需覆盖）：

```bash
set -a; source .env.local; set +a   # SSO_CLIENT_ID/SSO_CLIENT_SECRET 随进程注入
mvn spring-boot:run
```

> **IDEA 启动**：IDE 不读 `.env.local`——SSO 变量须加进 Run Configuration →
> Environment variables（或装 EnvFile 插件勾选该文件）。漏注入的症状：BFF 302 出去
> `client_id=` 为空 → identity 报 `unauthorized_client: client_id 缺失` 跳 `:10002/error`。

冒烟登录（cookie-jar 走完整授权码链，供后续 `curl -b` 验收）：

```bash
./scripts/login.sh                  # 凭据从环境或 .env.local 读；默认 jar 在 /tmp/aiplatform-cookie-jar
curl -b /tmp/aiplatform-cookie-jar localhost:8888/api/me     # → {accountId, displayName}
```

- 无会话访问 `/api/**` → 401（统一信封）；`/auth/**`、swagger、actuator 可匿名可达。
- 服务重启 → 内存会话丢失 → 再走一次 `login.sh`：identity 侧 SSO 会话仍在，**免密码**
  直通回调（浏览器同理由 middleware 302 到 `/auth/login?returnTo=…` 弹回一次）。
- 登出：`curl -X POST -b jar localhost:8888/auth/logout` → 302 identity 清 SSO 会话后
  回 `http://localhost:3333/`（`post_logout_redirect_uri` 独立白名单）。
- identity 联调注意（2026-08-22 实测）：① identity 本地未配 PEM 密钥，**每次重启换临时
  密钥而 kid 固定**，本服务 JWKS 缓存 24h 只按「kid 未命中」重拉——identity 重启后本服务
  **也要跟着重启**（顺序：先 identity 后 8888），否则验签静默失败（`/?error=exchange_failed`）。
  ② identity id_token 的 `aud` 灌的是其全局 `identity.token.jwt.audiences`（「按 client_id
  覆盖 aud」是其 Phase 2 未落项）——本地已在 aieducenter-identity 的 application-local.yml
  把本平台 client_id 追加进 audiences 兜底，identity 侧正修落地后可撤。
