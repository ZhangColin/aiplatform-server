## 架构落点

- **事件桥**：映射表单点 `AgentscopeEventMapper`（infra）——过程帧 `text`/`reasoning`（data.delta 增量）、`tool`（start/end 两帧）、`step-start`/`step-finish`（模型调用边界）；生命周期帧 `task-start`/`session-created`/`task-finish`（finish=end|exceed_max_iters）/`error`。端口改 `converse(command, Consumer<AgentEvent>)`（`ChatAgentProgress` 退役），`streamCorrelation` 随命令进（禁 `type` 键，对齐 `AgentRunContext` 口径）。
- **工作区桥**：`ChatAgentWorkspace` sealed（`Local` 兜底 = #44 配置路径；`ProjectDev` = 容器文件面）。工厂分型构建：ProjectDev 走 `abstractFilesystem(DockerExecFilesystem)` + 名义根 `/workspace`，并 `disableSubagents/disableMemoryHooks/disableMemoryTools`（harness 内脏不进项目工作区——源码包是交付物；2.0.1 无 transcript 部件）。容器不在 → 各操作 fail 结果如实暴露。
- **口径**：`session-created` 按进程内首见集合发射（复用不发）；重启后首见会重发是已知过渡行为，持久化归 #48。

## 已知取舍（Phase A）

- `DockerExecFilesystem`：每操作一次 `docker exec`（fork 开销换零拓扑改动——编码引擎共用同一容器）；grep 结果按 `路径:行:文本` 解析（文件名含冒号会错位）；glob 用 Java PathMatcher（`**` 跨目录、无零段特例）。
- read 按扩展名判二进制（与 FilesystemUtils 常用集对齐）。
- 名义根：agent 看到的路径即容器工作区锚定形（`/docs/PRD.md`），与编码引擎视图一致。
